Icon Button Guidelines

Icon buttons provide a compact way to trigger actions while maintaining clean interfaces. Since icons communicate meaning without text, choosing the right icon and providing clear tooltips becomes critical for usability. The IconButton component ensures consistent styling and behavior across all icon-based actions.

Icon Selection

Choose Recognizable Icons

Use icons that clearly represent their action. When in doubt, prioritize universal symbols over creative interpretations.

Do

  • Magnifying glass for search
  • Pencil or edit icon for editing
  • Download arrow for downloads
  • Settings gear for configuration

Don't

  • Abstract or ambiguous icons that require explanation
  • Icons that could have multiple interpretations
  • Custom icons when standard ones exist

Icon Meaning Consistency

Use the same icon for the same action throughout the application. Users learn and expect consistency.

Do

Use the same edit icon across all edit functions in your app.

Don't

Use different edit icons (pencil, pen, edit text) for similar editing actions.

Tooltip Guidelines

Always Provide Tooltips

Every icon button must have a descriptive tooltip that clearly states what will happen when clicked.

Do

  • "Delete item"
  • "Edit profile settings"
  • "Download report as PDF"
  • "Close dialog"

Don't

  • "Delete" (too vague)
  • "Edit" (edit what?)
  • "Download" (download what format?)
  • "Close" (close what?)

Tooltip Language

Use action-oriented language that describes the outcome, not just the icon name.

Do

"Remove item from list" instead of "X button"

Don't

"Trash can" or "Delete icon"

Close vs Delete Icons

Understanding when to use close versus delete icons is crucial for user expectations and preventing destructive actions. This is a common source of confusion that can lead to inconsistent user experiences.

Use Close icon for:

Temporary removals or dismissals:
  • Recommended in most cases but can be skipped occasionally
  • Rare exception: large and complex modals where actions happen inside the content area
  • Main action buttons always aligned to the right
  • Primary action positioned far right

Characteristics: Reversible, non-destructive, affects UI state rather than data.

Use Delete icon for:

Permanent data removal:
  • Deleting files, records, or database entries
  • Removing user-created content permanently
  • Deleting accounts or user profiles
  • Deleting articles

Characteristics: Usually irreversible, destructive, affects actual data.

Examples

Do - Close icon

  • Closing a modal dialog: "Close dialog"
  • Removing an item from related content: "Remove from related"
  • Dismissing a notification: "Dismiss notification"
  • Closing a sidebar: "Close preview"

Do - Delete icon

  • Deleting a user account: "Delete account permanently"
  • Removing a saved document: "Delete document"
  • Deleting a database record: "Delete customer record"

Don't

  • Using trash icon to close dialogs or dismiss notifications
  • Using close (×) icon for permanent deletions
  • Mixing these icons inconsistently for similar actions

Accessibility Considerations

Color and Contrast

Icons should meet accessibility contrast requirements. Don't rely on color alone to convey meaning.

Screen Readers

The IconButton component requires an ARIA label as a mandatory prop, which serves dual purposes: providing screen reader accessibility and generating the tooltip text. Screen reader support is built directly into the component.

Component Usage

  • IconButton: Use for all icon-based actions with proper icon selection and mandatory tooltips for clear user communication.
  • ButtonGroup: When grouping multiple icon buttons, use the ButtonGroup component for consistent spacing and alignment. The same spacing principles that apply to regular button grouping apply here.
